Eagle Vision School Management System

Web-based records, attendance & grading system — built for an operating school

Case 01 · Solo Capstone

The Problem

Eagle Vision Basic School (~250 students, 13 classes, 12 teachers) tracked attendance, grading, and fee collection manually — slow to update and easy to get wrong.

What I Built

A full system for student records, attendance, class/subject management, GES-standard grading (class score + exam score → grade 1–9), and fee/finance tracking — now used operationally by school staff.

Technical Highlights

  • Hardened the codebase against SQL injection using prepared statements throughout
  • Escaped all user-supplied output through a centralized htmlspecialchars() helper, applied consistently across the codebase
  • Built login-attempt limiting — 5 attempts, 15-minute lockout with a live countdown
  • Designed a 10-table relational schema, including per-term student remarks

SmartPay

Multi-tenant fee collection & SMS payment platform for Ghanaian schools

Case 03 · Solo Founder & Builder

The Problem

Schools in Ghana still chase fees with printed bills, phone calls and handwritten records — it eats the bursar's time every term, and unpaid balances get missed.

What I Built

A multi-tenant fee platform: admins set fee structures per class and term, SmartPay generates invoices and texts parents a payment link, and parents pay by Mobile Money or card through Paystack on any phone — no app required. An AI-generated daily summary (Google Gemini) gives the office a plain-English read on collection progress.

Technical Highlights

  • Next.js frontend (Vercel) and Express/Node backend (Render) on MySQL, backed by a 44-file automated test suite (Jest + Supertest)
  • A startup config validator that refuses to boot on a missing secret rather than failing silently — written after a real incident where a missing JWT_SECRET broke every login while the health check still said "running"
  • Scheduled jobs — Friday reminders, payment reconciliation, nightly backups — authenticated via a dedicated secret, separate from user login
  • Per-school data isolation with an audit log for every fee edit and voided payment, plus rate limiting and security headers on every request
